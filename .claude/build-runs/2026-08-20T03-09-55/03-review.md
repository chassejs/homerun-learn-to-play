## Summary

The build delivers what `01-plan.md` specified: a vanilla, build-step-free single-page app that teaches baseball across 24 chapters in 6 tiers, places the learner with an adaptive quiz, tests retention with per-chapter quizzes feeding a spaced-repetition deck, and measures a 40–160 Baseball IQ from a 361-question bank. It is roughly 32,400 lines of application JavaScript plus a 2,190-line brand stylesheet, with 300 lesson sections, 205 glossary terms, 13 SVG diagram builders, and 16 interactive widgets.

Quality is high where it matters most. The baseball content is written from the Youth Baseball Canada knowledge base rather than from memory, and it shows: Chapter 17 states all four infield-fly conditions correctly, separates what the rule does from what it does not do, and carries a division-applicability table that explicitly flags where the source is uncertain ("not confirmed as universal — verify with the provincial association") instead of inventing a confident answer. Chapter 22 defines each statistic by the question it answers and what it hides, and avoids asserting current league constants. The assessment logic is correct under adversarial testing: the choice-shuffling function held its answer invariant across 200 randomized runs without mutating its input, BBIQ stayed inside 40–160 including the zero-difficulty edge case, and the placement tier formula returned a valid 1–6 across the full theta × self-report × role cross-product with the coach floor intact.

Nine defects were found and fixed during review, five of them systemic. Two were mine rather than the implementer's: the chunk-2 brief specified an invalid `height="auto"` on the SVG root, and the initial scaffold silently skipped the one shared file living inside `tests/`. The two most consequential were found only by driving the **deployed** site rather than the local build — a stale-click/overshoot hole in the question runner, and class writes that fail silently on SVG elements, which had disabled hotspot feedback entirely. Nothing known is left broken.

## Issues

- [MAJOR — fixed] Every `HRL_SVG` builder emitted `height="auto"` on the root `<svg>`, which is not a valid SVG length. A page with 15 diagrams logged 15 console errors. **This originated in my chunk-2 brief, not in the implementation.** Removed the attribute and added an explicit `.hrl-svg` sizing rule.
- [CRITICAL — fixed] `src/glossary-data.js` was missing a comma after the `short:` property of the `courtesy-runner` entry — a hard `SyntaxError` that prevented the entire 205-term glossary from loading. Every property line in the file was scanned for the same pattern; this was the only occurrence.
- [MAJOR — fixed] Every module-rendered view showed its `index.html` placeholder heading and hint above the module's own header, so the chapter reader displayed a bare "Chapter" and a generic instruction line above the real chapter title, and the placement screen showed its heading and intro sentence twice. Fixed by adding `HRL_SHELL.setViewHeading` as a single shared implementation and having all four modules take ownership of their view's heading.
- [MAJOR — fixed] All 25 interactive sections rendered their heading twice — once as the section heading, once inside the widget's header bar. Fixed once in the widget registry rather than in all 16 widgets: the `.widget-head` is suppressed when its text matches the enclosing section's heading.
- [MINOR — fixed] All six tiers pointed `heroImage` at `brand/hero-tier-N.jpg`. No raster art exists or can be generated in this environment, so each chapter load fired a 404. The `onerror` fallback worked, but a handled 404 is still a logged console error. Set to `null` with the path documented inline for whenever real art is added.
- [MINOR — fixed] `tests/versionCompat.test.js` was never copied during scaffolding — **my error**, from a copy loop that iterated only over repo-root files. Copied it with the namespace rewrite, and replaced its two `practice.js` normalizer tests with equivalent `progress.js` checks.
- [MINOR — fixed] `changelog.js` retained the Practice Planner's release notes verbatim ("368 drills", "multi-station mode"). Version metadata was correct, so the consistency test passed and the wrong copy would have shipped into the in-app What's-New modal. Replaced with this app's actual feature set.

- [CRITICAL — fixed] Hotspot questions gave **no feedback at all**. `HRL_SVG` emits hotspots as SVG `<g>` elements, where `className` is a read-only `SVGAnimatedString`; assigning a string to it is silently ignored — no exception, no effect. Measured on the deployed site: after the assignment `getAttribute('class')` was unchanged. `quiz.js` `markHotspots()` used exactly that pattern, so clicking a fielder never marked it right or wrong and never revealed the correct answer. 15 hotspot questions exist and 4 sit in chapter quizzes (ch11, ch12, ch13, ch14), so ordinary learners hit it. The pattern was codebase-wide — zero `classList` usage and several raw `className =` writes including each file's element-builder helper, which the widgets use to mark hotspots too. Fixed with SVG-safe `getClass`/`setClass`/`addClass`/`removeClass` in `quiz.js`, `iq.js`, and `interactive.js`, every call site routed through them, plus `.hrl-hotspot` correct/wrong/selected CSS using the teaching tokens with a 4px stroke so the cue is not colour-only. Verified in-browser: clicking the wrong fielder marks it `selected wrong`, the correct one is revealed as `correct`, and the explanation renders.
- [MAJOR — fixed] The question runner could be advanced by a **stale, detached** "Next" button, and overshooting the last question cleared `#quiz-root` and rendered nothing — a blank page inside the quiz view with no way out, with the attempt never recorded despite misses reaching the review deck. Reachable by a fast double-click on the final question. Fixed with a monotonic render token so superseded handlers are inert, a `finished` flag so the result renders and records exactly once, an explicit bounds branch, and a never-empty safety net; the same guards were applied to `iq.js`. Verified on production: two clicks on a detached button leave state completely unchanged, and hammering the result-screen buttons does not double-record the attempt.

- [MINOR — accepted, not a defect] No raster hero images exist. This environment has no image-generation capability, so the visual system was built to be complete without them: a `tierHero` SVG builder draws six distinct illustrated banner scenes (golden-hour gradients, silhouette figures only, no faces), and `design/hero-image-prompts.md` carries six Grok Imagine prompts should the user want raster art later. The app is designed to render correctly either way.
- [MINOR — accepted] Running the suite on Node 26 prints an `ExperimentalWarning` about `localStorage`. It comes from Node's own global, not from unguarded access — every `localStorage` call in `progress.js` is inside try/catch — and it does not affect any result.
